## 要望との対応
1. **炎・龍・祝福を別物に**: 開始BGMは v49 のまま3種別。開始の気配(熱気/稲光/金の光)、フリーズ後の亀裂の造形と色、上昇音の音色(炎=歪んだ鋸歯波+火の粉 / 龍=低い龍鳴り+水のきらめき+雷 / 祝福=鐘の分散和音+金粉のシマー)、解放の和音を3種別にした。
2. **開始から迫力**: 剣・龍・宝箱は v49 の大きな登場を継承し、0.75秒で叩きつけるように着地→着地で衝撃波+フラッシュ+カメラ押し。カメラが寄る動き(1.16→1.0)と光の走りを追加。
3. **フリーズ→降臨**: プチュン(既存)→暗転3秒(既存)→亀裂5秒→エネルギー7秒(計約12秒・参考音源の長さに同期)→虹色→景品。FreezePatterns.insert が以後の場面を全部切るので、フリーズ後にプレミア等が重なることはない(v49から継承・確認済み)。
4. **亀裂・虹色エネルギー・稲妻**: 亀裂は 奥の暗い溝/縁/芯の3層+先端の光、火花が先端から飛ぶ。龍は亀裂の先端から枝分かれする稲妻(本数が進行で増える)。進行で衝撃波・揺れ・色ずれが強まる。
5. **文字**: 縁1.5px+6段の押し出し影+光。登場は 2.4倍→縮んで着地→2回の小さな揺れ。「届かず…」は銀の重い文字が落ちて割れ、画面が一瞬沈む。320/375/430px幅で全見出しの文字幅が画面内に収まることを実測(下記)。
6. **音**: 参考音源 descent-reference.mp3 を解析(0〜5.2秒 緊張/5.2〜7.5秒 静寂/7.5秒〜 最高潮/11.8秒 解放)し、フリーズの長さをそれに合わせた。**公開用は参考音源そのものを使わず、同じ構造・同じ長さ(12.6秒)のオリジナル(138BPM: 唸りと刻み→心拍と膨らみ→四つ打ち+半音ずつ上がる和音+高いアルペジオ+上昇ノイズ→全帯域の炸裂)を合成して差し替えた**。プチュン(ピッチ急降下+ブラウン管の鳴き+途切れ)と炸裂もオリジナル。追加層はこの音より小さい音量で重ね、鼓動は間隔が1.1秒→0.18秒に縮む。高域シェルフで全体の高音を持ち上げ。亀裂が走る瞬間に「ピシッ」、稲妻に「バチッ」、解放に全帯域の一撃+明るい和音。
7. **PUSH前の期待感**: v49 の「来るか…？」(出そうで出ない3回)を継承し、心拍(70→170bpm)に同期して画面の縁が赤く脈打ち文字が跳ねる。PUSHが出た瞬間に金属の一撃+衝撃波。出ない時(pushvoid)は下降音。
8. **虹色メダカと祝福**: メダカは画面内(inset 17% 12% 30%)。「おめでとう！」は光線が回り、光が脈打つ。B/C賞では「○賞 獲得」の銀文字に変わり、光線は出ない。

## 確認したこと
- **公開ページ(https://claude.ai/artifact/HFQW9C4SjqyXduWv5TZbre ・非公開)を社長PCのChromeで通し再生**: 炎(iframe・フリーズ)/龍(フリーズ)/祝福(PUSH後フリーズ)の3本を最後まで止めずに再生し、開始→PUSH→プチュン→暗転→亀裂→エネルギー→虹→景品の流れが崩れないことを3秒ごとの静止画で確認。コンソールのJSエラーなし。
- ローカル(スマホ幅375×812)では場面を直接指定して、龍・祝福・炎の亀裂/エネルギー、届かず、C賞の当選、虹、PUSH前の煽りを静止画で確認。開発中に出たJSエラー2件(ellipseの負の半径)は修正済み。
- 文字の収まり: 320/375/430px幅で、見出し10種(灼熱崩壊・炎神覚醒・咆哮・おめでとう！(虹と当選の2か所)・極彩降臨・届かず…・来るか…？・極彩覚醒・龍神降臨)の文字インク幅がすべて画面内(アニメーション中央時点で実測)。
- 炎の当選画面: SS RANK / 魚 / おめでとう！ / 極彩降臨 / 景品名 が上から順に重ならず並ぶ(矩形で実測)。v49では「おめでとう！」と「極彩降臨」が重なっていた。
- 音(OfflineAudioContextで、参考音源+上昇音+亀裂音11発+稲妻(龍)+解放の一撃を本番と同じ時刻に鳴らし、本番と同じ高域シェルフ+音量0.82を通して13.5秒レンダリング。リミッターの手前の値):

  |---|---|---|---|---|
  | 参考音源のみ(同条件換算) | 約-8.8 dB | 0 | 約-24.3 dB | 約-23.4 dB |

  高域が+4.5〜5.4dB、低域は+0.4〜3.0dB(=高音が際立つ方向)。最初の版は解放の一撃で+2〜3dB・クリップ16〜27サンプルだったので、一撃と稲妻の音量を下げて0dB未満にした。0.5秒ごとの音量包絡は参考音源の「静寂→最高潮」に追従。

## 11/27 本番の配線(アテナさん確認事項への回答・v50d・?v=56)
**方針: URLの等級指定(?rank=)は景品の根拠にしない。景品はサーバーの記録だけ。**
- 抽選と記録: 播州オクのサーバー(src/lib/oripa.ts draw)がトランザクション内で抽選し、oripa_draws に「誰が(user_id)・どの注文で(order_id)・どの箱で(package_id)・何を(prize_id・prize_name・rarity)」を保存する(以前から)。
- 読み口(新規): GET /api/oripa/draws/<記録ID>。ログイン中の本人の記録しか返さない(他人のIDは404、未ログインは401)。等級・景品ID・名前・画像・箱名を返す。何も決めない。
- 演出ページ(変更): ?draw=<記録ID> で開くと上のAPIを読み、等級(S賞→SS/A賞→S/B/C)・景品名・画像・記録IDを画面に出す。**?rank= は本番モードでは無視**(URLを書き換えても記録どおり)。「もう一度見る」は同じ記録を再生するので景品ID・名前・画像まで同じ。記録が読めなければ再生しない。
- 播州オクの導線(新規): 当選直後のモーダルに「🎬 一番良い当たりの演出を見る」、くじページの当選一覧に「演出を見る」(いずれも /gacha/index.html?draw=<記録ID>)。再表示はここから。
- 旧 ?rank= 指定は、記録IDの無いデモ(お試し)専用。
- ローカル(localhost:3012)で通し確認: 会員登録→承認→3口購入(テスト決済)→1口抽選(B賞「テストB賞 楊貴妃 ペア」記録ID1)→モーダルに演出リンク→ /gacha/index.html?draw=1&rank=SS を開く→ ?rank=SS は無視され B で固定(3回選んでも B)・設定欄非表示・「もう一度見る」→ 当選画面と結果画面に「B賞 獲得」「テストB賞 楊貴妃 ペア」「記録ID 1」。他人のID(999)は404、未ログインは401。
