# 播州オク デプロイ手順・開業チェックリスト

社長が上から順に進めれば開業できるように書いています。
技術的な仕込み（Docker化・永続化・本番ガード）はこちらで完了済みです。残りは「アカウントを作って鍵を入れる」だけです。

---

## 0. 全体像（3つだけ）

1. **公開する場所を1つ契約する**（コンテナを動かせて、消えないディスクが付くところ）
2. **GitHub のこのリポジトリをつなぐ**（または Docker イメージを置く）
3. **環境変数（鍵と設定）を入れて起動**

決済・LINE・メールは「鍵を入れたら有効、入れなければ無効（テスト動作）」です。鍵なしでも起動はします。

---

## 1. どこに公開するか

このアプリは **SQLite（1ファイルのデータベース）** と **画像ファイル** を `/data` に保存します。
なので **「消えないディスク（永続ボリューム）が付くコンテナホスト」** を選びます。Vercel の無料枠のような「毎回まっさらになる」ところは不可です。

おすすめ（どれか1つ）:

| 選択肢 | 向いている人 | 永続ディスク |
|---|---|---|
| **Fly.io** | 安く始めたい。CLIを少し使える | あり（`fly.toml` を同梱済み） |
| **Railway** | 画面でポチポチしたい | あり（Volume を /data に） |
| **Render** | 画面でポチポチしたい | あり（有料プランの Disk を /data に） |
| **自前VPS（さくら・ConoHa等）** | 慣れている | ディスクそのまま。`docker compose up -d` |

どれを選んでも、同梱の `Dockerfile` がそのまま使えます。
**重要：SQLite構成なのでサーバーは1台だけで動かしてください（複数台に増やさない）。**

### 例A：Fly.io（CLIで3コマンド）
```bash
# 1. flyctl を入れてログイン（初回のみ）
curl -L https://fly.io/install.sh | sh
fly auth login

# 2. アプリ作成（fly.toml の app 名を自分のものに変えてから）
fly launch --no-deploy        # 既存の fly.toml / Dockerfile を使う
fly volumes create banshu_data --size 1 --region nrt   # 永続ディスク1GB

# 3. 鍵を設定してデプロイ（鍵は下の表参照）
fly secrets set OTP_SALT="（ランダムな長い文字列）" BASE_URL="https://<アプリ名>.fly.dev"
fly deploy
```

### 例B：Railway / Render（画面）
1. GitHub のこのリポジトリを連携して「Dockerfile からデプロイ」を選ぶ
2. **Volume（永続ディスク）を作って、マウント先を `/data` にする**
3. 環境変数（下の表）を入れる
4. デプロイ。公開URLが出たら `BASE_URL` にそのURLを設定して再デプロイ

### 例C：VPS（自分のサーバー）
```bash
git clone <このリポジトリ> && cd my-first-pr
cp .env.example .env    # .env を編集して鍵を入れる
docker compose up -d    # /data はボリュームに永続化される
```

## 2. 環境変数（鍵と設定）

`.env.example` に全項目があります。**必須**から埋めてください。

### 必須
| 変数 | 内容 | 取り方 |
|---|---|---|
| `OTP_SALT` | 認証コードの安全性の要。長いランダム文字列 | `openssl rand -hex 32` の出力を貼るだけ |
| `BASE_URL` | 公開URL（例 `https://banshu-oku.fly.dev`） | デプロイ後に出るURL |
| `ADMIN_EMAILS` | 管理者にするメール（自分のメール） | 自分のアドレス。これでログインすると管理画面が出る |

### 強く推奨（無いと通知が届かない）
| 変数 | 内容 |
|---|---|
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `MAIL_FROM` | 認証コード・落札通知メールの送信。SendGrid / Amazon SES / さくらのメール等の情報を入れる |

### お店の情報（特商法。生体販売なので必須級）
`LEGAL_BUSINESS_NAME` `LEGAL_REPRESENTATIVE` `LEGAL_ADDRESS` `LEGAL_PHONE` `LEGAL_EMAIL` に実際の屋号・氏名・住所・電話・連絡先を入れる。

- LINE（通知・ログイン）… 第5章
- `PAYMENT_BANK_INFO`（振込先）、`FEE_PLANS`（手数料率）、`RANKS`（会員ランク）など

## 3. 最初の設定（公開直後に1回）

1. 自分のメール（`ADMIN_EMAILS` に入れたもの）で **ログイン** → 「管理」メニューが出る
2. 「出品者管理」で **出品者（播州めだか など）を登録**
3. 出品者に会員（メール）を紐づけ、**PINコードを発行**（出品者に伝える）
4. 「新規出品」で試しに1件出す → 会場に出るか確認
5. 「瓦版・告知」「ガチャの景品」などは必要に応じて

## 4. オンライン決済（Stripe）を有効にする

入れなくても銀行振込・出品者LINE決済で運用できます。カード/PayPayを使うなら:

1. Stripe に登録し、本番用の **シークレットキー**（`sk_live_...`）を取得 → `STRIPE_SECRET_KEY` に設定
2. Stripe ダッシュボードの「Webhook」で宛先 `https://<あなたのドメイン>/api/payments/webhook` を追加し、イベント `checkout.session.completed` を送る設定にする → 表示される **署名シークレット**（`whsec_...`）を `STRIPE_WEBHOOK_SECRET` に設定
3. **PayPay** も使うなら、Stripe ダッシュボードの「決済手段」で PayPay を有効化（Checkout 画面に自動で出ます）
4. 出品者ごとに、出品者設定の「オンライン決済を受け付ける」を ON にする

カード番号は Stripe の画面で入力され、このサイトのサーバーには届きません（PCI対応の負担を負いません）。

## 5. LINE（任意）

- **通知**：LINE Messaging API のチャネルを作り `LINE_CHANNEL_ACCESS_TOKEN` `LINE_CHANNEL_SECRET` を設定。Webhook は `/api/line/webhook`
- **ログイン**：LINE ログインチャネルを作り、コールバック `https://<ドメイン>/api/line/callback` を登録、`LINE_LOGIN_CHANNEL_ID` `LINE_LOGIN_CHANNEL_SECRET` を設定

## 6. バックアップ（大事）

データは全部 `/data`（SQLiteファイルと画像）にあります。定期的に `/data` をコピー/スナップショットしてください。
- Fly.io: `fly volumes snapshots` が自動取得。手動DLは `fly ssh console` から `/data/auction.sqlite` を落とす
- VPS: `docker compose cp app:/data ./backup-$(date +%F)` など
