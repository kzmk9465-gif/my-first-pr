## 3. リアルタイム更新の仕組み（WebSocketは不使用）

- 価格は **公開REST** `GET /wp-json/eap-auction/v1/status/{出品ID}` をポーリング。返すJSONは title, current_bid, end_ts, force_end, last_bid_ts, history[{name, price, ts, auto}]。入札履歴の `auto` フラグで自動入札が分かる
- 画面側は `setInterval(render, 1000)` と `setInterval(sync, 1500)`。入札履歴HTMLは admin-ajax の `eap1yk_bidlog_html`
- **負荷対策**が徹底している：
  - 「EAP Poll Pause」：`window.setInterval` 自体を差し替え、裏タブの間は500ms〜60秒周期のポーリングを止める
  - `window.fetch` と `XMLHttpRequest` を差し替え、未ログイン時のフォロー状態取得など結果が決まっている admin-ajax 呼び出しはサーバーに行かずに固定JSONを返す
  - 入札履歴はボタンを押した時だけ読む（マイページ）
- admin-ajax の主なアクション：`eua_send_otp` / `eua_verify_otp` / `eua_logout`（認証）、`eapx_otp_send`、`eap_ec_get_cart` / `eap_ec_add_cart` / `eap_ec_update_cart` / `eap_ec_get_stock` / `eap_ec_place_order` / `eapcp_submit_checkout`（EC）、`eap1_toggle_fav`、`eamb_zombie_report`

## 4. 認証・不正対策（公開情報から分かる範囲）

- パスワード無し。メールの6桁OTP（LINE連携済みならLINEにも送る）。Cookie名 `eap_bidder_token`、nonce付き
- 会員登録フォームの項目：氏名、SNSアカウント（Instagram/TikTok、必須）、屋号（販売証明書に載る名前）、郵便番号、住所、電話、メール。ダブルオプトイン後に管理者が承認。登録情報を変更すると承認が外れ、公式LINEに連絡して再承認
- フォームにハニーポット（`easp_honey`）と表示時刻のタイムスタンプ
- 「ゾンビ検知」：ブロックされた端末は localStorage/sessionStorage に印を残し、再訪時に `eamb_zombie_report` を送って画面を「🚫 Detection」に差し替える（ブロック済みユーザーの再アクセス検知）
- セキュリティページの宣言：管理者は2段階認証、メール＋IPでブロック、同一IPのログイン失敗で15分制限、OTP送信の回数制限、xmlrpc遮断、画像のマジックバイト検証、設定ファイルへのアクセス遮断
- 証明書は「電子署名で封印」し、証明番号から誰でも照合できる

## 5. LINE の使い方

- LINE公式アカウント（lin.ee）＋ Messaging API：高値更新・落札・決済案内・発送通知・OTP・各種お知らせ。Webhookは署名検証
- LINEログイン（access.line.me）：ワンタップログイン、「わたしの取引のいま」はLINEログイン専用
- メンバーパスやECの購入には **LINE連携が必須**
- 会員出品の支払い・発送連絡は「出品者のLINE」で行う運用

## 6. 決済（ここが重要）

結論：**江戸オク本体はカード決済を自前で処理していない。** 決済はLINE経由の個別対応と、外部決済事業者のホスト型決済画面に逃がしている。

| 取引の種類 | 誰が売主 | 支払い方法 | 仕組み |
|---|---|---|---|
| 会員出品（委託・ブリーダー出品） | 出品者 | 出品者ごとに案内（カード等は出品者側で用意） | 落札後、落札者が「お手続き」で発送先・配送方法・支払方法を選び、**出品者のLINEに連絡して支払う**。代金は出品者が直接受領。サイトは取引ステータスを管理するだけ |
| 公式出品（目高工房江戸が売主） | 運営 | クレジットカード、PayPay、銀行振込 | 落札後に支払い案内が自動でLINEとメールに届く。決済画面は外部 |
| ECショップ（ENNMA飼料、電子書籍など） | 運営 | 決済画面に表示（カード・PayPay・振込） | カート→`eap_ec_place_order`（admin-ajax）→サーバーが返す `checkout_url` へリダイレクト。クーポンコード欄、常温/クール便、梱包オプションあり。購入にはログインとLINE連携が必要 |
| メンバーパス・応援ハート | 運営（役務） | クレジットカードまたはPayPay、その場で即時決済 | 「カード・PayPayを選ぶ画面に移ります」と案内。特商法に「外部決済事業者」「クレジットカード等への返金反映は各決済事業者の処理期間による」と明記 |

- 公開HTML・JSに Stripe / Square / KOMOJU / GMO / PayPay などの決済SDKやドメインは**一切含まれていない**（Stripeの文字はセキュリティ比較表に出るだけ）。決済事業者は、ログイン後の決済画面に遷移して初めて分かる構成で、カード番号がサイトを通らないホスト型を使っている
- セキュリティページには「クレジットカード番号・口座情報・決済データを一切保持していない」「落札後のお支払いは出品者と落札者の間でLINEを通じて個別に行う」と明記。PCI DSSの負担をゼロにする設計
- 支払期限は落札後24時間。前払い。落札後キャンセルは原則不可。前受金の保全措置は講じていないと表記
- 手数料プラン（10/30/50%）は「現在はご紹介のみ受け付け」。30%・50%プランは「決済と問い合わせ対応をエドオクが代行」と説明
- 落札者へのシステム利用料は「現在ありません」

## 8. 気づいた点（播州オクに活かす・避ける）

1. **決済を持たない設計は真似してよい。** 会員出品は出品者のLINEで決済、公式出品とパスはホスト型決済画面へリダイレクト。カード情報をサーバーに通さないので、PCI対応やカード不正の責任を負わずに済む。播州オクも Stripe Checkout / Square 決済リンク / PayPay のいずれかの「ホスト型」で、同じ構造にできる
2. **サブスク収益の二重取り。** Instagramサブスクとメンバーパスで同じ特典を売り、審査で落ちた人を自社に流している。割引コードを「本人専用」にして横流しを防いでいる
3. **証明書を有料化の入口にしている。** 二次販売証明は1枚100円だが、パス会員は無料。証明の系図が増えるほど会員が離れにくい
4. **リアルタイムは全部ポーリング。** WebSocket無しで、裏タブ停止・固定応答・履歴の遅延読み込みでサーバーを守っている。共有サーバーのWordPressでも成り立つ現実的な設計
5. **フリー素材をクレジット付きで使う。** VOICEVOX（利用規約でクレジット表記が必要）、CC BYのBGM。播州オクで声を付けるなら同じ手が使える
6. **注意点：** ENNMA HUB のページは Gemini API キーがブラウザ側のコードに埋め込まれている（第三者が流用できる状態）。播州オクでAIを使うなら、キーはサーバー側に置くこと。また、セキュリティページの「他社比較スコア」は自社計測の表示で、第三者認証ではない
7. **機能の肥大化。** サイトマップには 50 以上のページがあり、404のページ（live-control, wakuwakuauction, taihei2026 など）も複数残っている。創設者自身が「部品が300近くに増えた」と書いている。播州オクは必要なものだけに絞る方が運用が軽い
